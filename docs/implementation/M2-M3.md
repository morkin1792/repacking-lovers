Prerequisite: M1b-5 accepted. Read Architecture's trust configuration and build/sign sections.
Use the existing fixture runner and M1a rebuild/bootstrap helpers. Identity contracts, JNI,
selected split integration, public CLI and physical ARM acceptance are not prerequisites for
the first controlled HTTPS proof. This track does not accept those identity capabilities.

0. **Files:** resource-engine entries in the lock/corpus, baseline NSC fixture flavors,
   shared rebuild helper, `run T-T19`.
   **Steps:**

   1. Pin Apktool by version/hash, keep DEX raw with `-s`, and use the private framework cache
      `.work/tools/apktool-framework` for both decode and build. Start with the absent/existing/
      qualified NSC fixtures. If an authorized device is available, list candidates read-only with
      `pm list packages -3 -i`; select at most five named authorized apps for the initial corpus.
      Use explicit serial plus `pm path PACKAGE` and retain every installed member/hash. Do not
      turn discovery into a bulk install/replacement job. Keep split-set rows separate; until
      selected-set validation exists, record them unavailable rather than test the base alone.

   2. For each available selected input, run a no-policy-change resource decode/build, then the
      shared align/sign/apksigner verification path. Use fresh output directories. The pinned
      Apktool commands for a single-APK baseline have this shape:

      ```sh
      env JAVA_HOME="$REPACK_JDK" "$REPACK_JDK/bin/java" -jar .work/tools/apktool.jar \
        d -s --frame-path .work/tools/apktool-framework --output .work/outputs/resource-baseline/decoded .work/inputs/original.apk
      env JAVA_HOME="$REPACK_JDK" "$REPACK_JDK/bin/java" -jar .work/tools/apktool.jar \
        b --frame-path .work/tools/apktool-framework --output .work/outputs/resource-baseline/unsigned.apk .work/outputs/resource-baseline/decoded
      ```

   3. Record per-input stages `rebuild`, `insertion`, `install`, `launch`, `https`, with log paths,
      engine/version/hash and exact denominator per stage. Baseline success does not mark later
      stages passed. Tasks 1–2 below perform actual CA/NSC insertion and runtime checks on fixtures;
      authorized target runtime measurements may follow under the calibration packet. Keep absent
      targets/device authorization as not-run prerequisites, not unsuccessful trust measurements.

   4. On a concrete Apktool resource-engine failure, trial one APKEditor/ARSCLib implementation:
      pin release/revision, dependency closure/license/hashes and implement only the required binary
      resource/manifest edits. Run the identical insertion/policy/runtime fixtures before promoting
      it to the fallback. Do not create a second generic resource-engine framework or switch
      engines silently. Preserve failing inputs and the fallback selection reason.

   **Check:** `python scripts/acceptance.py run T-T19 --device "$REPACK_SERIAL" --out .work/evidence/T-T19.json`.

   **Pass:**

   - screening report has a bounded inventory, complete baseline stage outcomes and
     per-stage numerators/denominators; the selected engine rebuilds the required fixture inputs.
     Corpus target failures stay failed; any fallback is named and awaits the same T-T20/T-T21 oracle.

   **Fail→:** if no engine rebuilds a required fixture, block M2. Other corpus failures narrow
   coverage; unavailable optional real targets do not block the first controlled HTTPS proof.

   **Interpretation:** a round-trip pass rate measures the tested inputs/stage only, not working
   trust insertion, installed-app compatibility or universal resource support.

## M2-DEX — optional runtime trust experiment

Prerequisite: M2 accepted on the selected cell. This experiment is eligible after M2 but does not
block M3, the default schedule or RELEASE-1's resource-trust claim. Reuse the one pinned bypass
implementation; pin it here if A has not yet needed it, without requiring identity acceptance.
Read Architecture's trust configuration section and the pinned API35 provider/config sources.

1. **Files:** `shim/.../RuntimeTrust.java`, Hidden.java entries, internal spike runtime-trust mode,
   late/factory TLS fixture variants, corpus and `run T-T23`.

   **Steps:**

   1. Inventory the exact constructor/method/field descriptors and CSV flags for ApplicationConfig,
      ConfigSource, NetworkSecurityConfig/Builder, CertificatesEntryRef, KeyStoreCertificateSource,
      ConfigNetworkSecurityPolicy and libcore.net.NetworkSecurityPolicy. The core API35 source/
      default-instance methods are max-target-o; CT-related members include blocked entries.
      Use public android.jar plus Hidden.java/reflection as specified in Architecture; initialize
      the same pinned process-local bypass before this experiment's hidden access in initLate.
      Record that bypass use even when A is disabled. Embed only public CA DER bytes in DEX.
   2. After platform NSC provider installation and before delegating instantiateApplication, read
      ApplicationConfig.getDefaultInstance. Parse/snapshot its effective default and per-domain
      configurations under the original configuration's locking contract. Use its source if
      available; handle the already-initialized state through the pinned mDefaultConfig/mConfigs
      representation rather than assuming mConfigSource survives initialization. Preserve original
      domain objects, domain matching and every original effective certificate-entry reference.
      Use a public in-memory KeyStore containing the verified CA, reflectively construct the
      framework KeyStoreCertificateSource, and construct CertificatesEntryRef(source, true).
      Do not implement an always-accept CertificateSource or reimplement issuer/signature matching.
   3. Build a fresh config for each distinct original configuration using the reflected Builder.
      Copy cleartext, HSTS, pin set, CT state and original entry references into independent lists,
      then add the test entry. Builder.setParent accepts a Builder, not an existing config, so
      it is not a cloning shortcut. Return the new default/per-domain sets from a ConfigSource
      dynamic proxy, preserving null/empty and Object-method semantics. Construct a replacement
      ApplicationConfig and verify policy equivalence except the intentional test anchor before
      publication. Inventory the installed ConfigNetworkSecurityPolicy's retained original config;
      the first trial retains that policy binding and requires identical per-host cleartext/CT
      observations against the copied configurations. A mismatch fails this trial rather than
      triggering an unplanned policy rewrite. Retain the existing provider installation and order.
   4. Publish with ApplicationConfig.setDefaultInstance only after the copy is complete. Retain
      original bindings for recoverable-failure rollback. Exercise fresh NSC-aware clients started
      in the Application and deliberately precreated factory TLS clients separately. A replacement
      does not repair previously captured TrustManagerFactory/SSLContext/socket-factory references;
      do not reset all default TLS objects to hide the timing gap. Run the same absent/existing/
      qualified/nested-domain anchor and wrong-chain controls as M2, with a second-app isolation
      control and explicit CT comparison on a separately available API36 cell if claiming it.

   **Check:** `python scripts/acceptance.py run T-T23 --device "$REPACK_SERIAL" --replace-existing-and-wipe-data --out .work/evidence/T-T23.json`.

   **Pass:**

   - Manifest/resources payload hashes remain identical to input; the public test CA is carried in
     DEX, and fresh covered clients yield marked decrypted HTTPS plus the expected app response.
   - Original domain/pin/cleartext/HSTS/CT behavior is preserved outside the explicit anchor allowance;
     wrong chains still fail and the second app's trust is unchanged.
   - Events record provider/default-instance state, publication time, access pin, rollback and
     fresh/precreated client outcomes. Precreated-client gaps stay explicit, not labelled covered.

   **Fail→:** isolate access, copying, late timing, retained TLS objects and trust-chain failures.
   Keep the failed experiment and resource M2 results separate; do not silently replace the default
   trust engine or add a public mode/flag. If copying cannot preserve a required policy, leave
   runtime-nsc unsupported on that cell. Missing optional API36 evidence excludes that CT claim.

   **Stop/next:** `gate M2-DEX` accepts only T-T23's declared fresh-client scope. Record
   `trust_mode: runtime-nsc` separately from `resource-nsc`; continue the next eligible core packet.

   **Interpretation:** initLate follows API35 provider installation, but factory code can create
   TLS objects earlier; one static default swap is not universal or cross-release trust coverage.

## Evidence-only target calibration after M2

When an authorized operator target is available, run a small calibration without waiting for
RELEASE-1. Record authorization/scope, immutable input/hash, target SDK/ABI and selected device.
General targets need the limited triage needed for this run; do not assume the fixture's factory,
keys, ABI or ZIP layout. Extend spike.py's existing patch interface with a trust calibration mode
only; this is not an early general public CLI. Identity/native/split features not yet implemented
remain unavailable, not simulated.
This internal `--mode trust` calibration combines accepted bootstrap/routing and NSC insertion;
it is distinct from public `--trust-only`, which intentionally makes no routing change.

```sh
python scripts/spike.py patch --input "$REPACK_TARGET_APK" \
  --out .work/outputs/target-calibration --key "$REPACK_OPERATOR_KEY" \
  --mode trust --ca "$REPACK_CA_CERT" --proxy "$REPACK_PROXY_ENDPOINT"
```

Resolve these variables from the authorized operator input; they are not existing files. The
endpoint defaults to 127.0.0.1:8080 when omitted; an explicit non-loopback endpoint needs separately
observed reachability. Update task 0's corpus stage records with these actual calibration results.
The
patch command builds only. Before any target installation, execute R-INSTALL using the selected
serial and explicit data-loss authorization if necessary; never reuse fixture-only replacement
authorization for a user package. If installation is not authorized, retain build/triage evidence
and leave runtime fields not-run.

Record separate observations for bootstrap ran, route hit, trust succeeded, pinning patched,
self-check tripped, and the tested action/log window. At M2, programmatic pinning may still fail;
repeat after M3 or a named identity capability is available. Unknown/not-run values remain explicit.
The record is calibration, not a gate pass or broad compatibility claim, and feeds identity-track
priorities. Missing target/device access does not block fixture progress.
