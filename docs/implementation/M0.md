# M0 — local tools, fixtures and the first available cell

Read PLAN §1/§3/§7, CONTRACT and its glossary. Identity inventory/T-A06 belong to M1a task 3.

## 0. Initialize the local repository

**Files:** `.git/`, `.gitignore`, progress.md.

**Steps:**

1. Reuse an existing parent repository, or run `git init` here if absent.
2. Ignore `.work/`, credentials and generated build output before key generation.

**Check:** `git rev-parse --show-toplevel`; `git check-ignore .work/keys/fixture.pass`.

**Pass:** project root and ignored artifact paths are correct.

**Fail→:** fix root/ignore rules before staging.

**Interpretation:** local initialization does not create a commit or remote.

## 1. Lock installed tools and choose a device

**Files:** `config/implementation-lock.json`, `scripts/acceptance.py` host/device commands.

**Steps:**

1. Reuse installed build-tools 36.0.0, public android-36/android.jar and the installed JDK when
   aapt2/javac/d8/apksigner probes work. Compile Java with --release 8. Record exact versions,
   paths and hashes. Gradle, AGP, a wrapper and a JDK17 download are not fixture prerequisites.
2. Read `adb devices -l`. Prefer a connected authorized physical phone; record its actual API,
   ABI, target SDK and page size as the first cell. With several phones require an explicit serial.
3. If no phone is available, use an existing compatible emulator. Before provisioning a new
   x86_64 AVD check /dev/kvm and emulator -accel-check. If unavailable, record the device prerequisite
   blocked and complete local build work; an image download alone cannot resolve acceleration.
4. Capture device fingerprint/build type/policy and non-root shell identity. Record a separate
   release target only when it differs. API-specific identity work adapts in M1a/M1b; trust and
   routing results still name their actual OS/target/client cell.

**Check:**

```sh
python scripts/acceptance.py host --out .work/evidence/M0-host.json
python scripts/acceptance.py device --out .work/evidence/M0-device.json
```

**Pass:** tools launch; a selected authorized serial and its properties match the cell lock.

**Fail→:** preserve host success and mark unavailable device execution blocked; continue task 2.

**Interpretation:** phone first is a selection rule, not permission to replace existing user apps.

## 2. Build release fixtures with SDK primitives

**Files:** `scripts/build_fixtures.py`, shared `repack/rebuild.py` primitives, Java sources/manifests
under `tests/fixtures/identity/`, `tests/corpus.json`.

**Steps:**

1. Create app/other fixtures, minSdk28/target35, non-debuggable. Use aapt2 compile/link, javac
   --release 8, d8 --release, ZIP assembly, zipalign -P 16 and apksigner. Use installed compileSdk36.
2. Create persistent original/other/repack local keys using CONTRACT. Export public cert DER and
   match SHA-256 against apksigner. Retain original artifacts and per-command logs/hashes.
3. Implement CONTRACT's actual direct/reflective signing queries and intent extras. Declare
   mutual package visibility. The default own factory has no initializer; add a CoreComponentFactory
   flavor from pinned androidx.core:core:1.15.0 (Google Maven AAR), keeping its required factory
   classes/dependency evidence. This is the one deliberate bootstrap dependency flavor.
4. Compile fixture NSC permitting cleartext for 127.0.0.1 only; keep the base policy restricted.
   This prepares T-N10's HTTP origin control, while target trust changes remain M2 work.

**Check:**

```sh
python scripts/build_fixtures.py --out .work/evidence/M0-build.json
```

**Pass:** signed APKs have expected packages, min/target SDK, release flags, resolvable NSC,
distinct original/other/repack certs and valid alignment/signatures. Both factory flavors build.

**Fail→:** fix the failed primitive or missing dependency; keep its actual output in evidence.

**Interpretation:** host build verification does not establish launch or signing-query behavior.

## 3. Run the baseline (T-A00) and accept M0

**Files:** `run T-A00` and `gate M0` in the one-file stdlib runner; corpus/progress.

**Steps:**

1. Preflight only the two inventoried fixture packages on the selected serial under R-INSTALL.
2. Run every active direct/reflective self/other query with host-exported expected digests.
3. Run the wrong-expected negative control and correlate fresh PID/window/token logs as CONTRACT
   specifies. Run both own and AndroidX factory flavors when their host artifacts are available.

**Check:**

```sh
python scripts/acceptance.py run T-A00 --device "$REPACK_SERIAL" --out .work/evidence/T-A00.json
python scripts/acceptance.py gate M0 --reports .work/evidence --out .work/evidence/M0.json
```

**Pass:** host/device/build reports pass; actual digests match host truth, direct/reflection agree,
and the wrong-expected comparison fails as intended. Gate reports bind immutable evidence/hashes.

**Fail→:** preserve the failed query or missing-device prerequisite; accept M0 only after its
observations exist. Device absence does not stop local fixture/tool work.

**Interpretation:** M0 has no hidden-API inventory/proxy/bypass requirement. Open BOOTSTRAP after
M0 acceptance; remaining identity work stays independent of first HTTPS proof.
